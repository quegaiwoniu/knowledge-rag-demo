# Day 4 AI 工作台与本机 JDK 启动说明

## 1. 这次做了什么

这次 Day 4 在原有后端 `/ai/extract` 接口基础上，补齐了两块更贴近真实业务开发的能力：

- 前端首页从“步骤演示页”升级为“AI 工作台”
- 新增“结构化抽取”能力卡，可直接联调 `/ai/extract`
- 后端新增固定本机 JDK 的启动脚本，减少 Java 版本漂移问题

## 2. AI 工作台包含哪些能力

当前首页已经统一整理为 4 张能力卡：

- AI 连通性验证
- 文本总结
- 结构化抽取
- RAG 能力预留

这样做的目标不是只完成当前 Day 4，而是为后续 Day 5 / Day 6 继续扩展能力提供更稳定的页面骨架。

## 3. 如何启动后端

推荐优先使用项目内脚本启动，而不是直接依赖当前终端的默认 Java。

### PowerShell

```powershell
.\scripts\run-backend.ps1
```

### cmd

```bat
scripts\run-backend.cmd
```

### 说明

脚本会在当前进程中显式设置：

- `JAVA_HOME`
- `PATH`

并固定使用这台机器上已经验证可用的 JDK：

```text
D:\SoftWare\IntelliJ IDEA 2026.1.3\jbr
```

## 4. 如何启动前端

在前端目录执行：

```bash
npm run dev -- --host 0.0.0.0
```

前端目录：

```text
D:\SoftWare\IdeaProjects\ragdemo\knowledge-rag-demo-web
```

## 5. 如何验证结构化抽取

启动前后端后，打开前端页面，在“结构化抽取”能力卡里：

1. 直接使用默认示例文本
2. 点击“发送 /ai/extract”
3. 观察返回的：
   - 标题
   - 分类
   - 优先级
   - 关键词

你也可以替换成更真实的业务文本，例如：

- 故障反馈
- 需求描述
- 客户投诉
- 咨询记录

## 6. 为什么要固定本机 JDK 启动

这个项目之前已经遇到过典型问题：

- 终端默认 Java 版本过旧
- Maven 能运行，但编译不过
- 不同终端结果不一致

把 JDK 切换逻辑收敛到项目脚本里，有几个好处：

- 启动方式更稳定
- 新终端/新电脑接手成本更低
- 更接近企业项目里的本地开发治理方式

## 7. 注意事项

- 本地 API Key 只保留在本机配置中
- 不要提交真实 API Key
- `application.yml` 中如果包含真实密钥，提交前必须再次检查
